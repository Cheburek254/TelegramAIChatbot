# TelegramAIChatbot

Telegram-бот для личных чатов. Помогает разобраться в теме, перевести текст и проверить код. Ведёт личное расписание, отправляет напоминания и может собирать ежедневную сводку. Можно запустить свой экземпляр на компьютере или на сервере.

## Что умеет бот

| Возможность | Как открыть |
| --- | --- |
| Объяснения с примерами и вопросы по материалам | `/study` |
| Перевод с сохранением структуры | `/translate` |
| Ревью кода с замечаниями по приоритету | `/review` |
| История диалога и настройка вариативности ответов | `/settings`, очистка через `/reset` |
| Личное расписание, редактирование и повторяющиеся занятия | `/schedule`, примеры в `/schedule help` |
| Личные задачи, дедлайны, завершение и перенос | `/tasks` |
| История задач, поиск и восстановление | `/tasks done [название]` |
| Свободные окна и напоминания о них | `/free 90 до пятницы` |
| Уведомления об изменениях в расписании ИТМО | `/itmo_alerts` |
| Учебный план в Telegram Mini App | `/app` |
| Разовые и ежедневные напоминания | `/reminders` и `/daily_reminders` |
| Погода и ежедневная сводка | `/city`, `/notifications` |
| Поиск по собственным заметкам и встроенным справочным материалам | `/materials` |
| Просмотр маршрута обработки запроса | `/why`, `/trace` |
| Подключение личного расписания my.itmo | `/itmo`, после [настройки интеграции](#опционально-расписание-итмо) |

История, настройки, расписание и заметки разделены по пользователям. Добавление и изменение личных записей требуют подтверждения в чате.

## Быстрый запуск с Docker

Нужны Git, Docker с командой `docker compose` и исходящий HTTPS-доступ к Telegram и выбранному провайдеру модели. Docker Desktop подходит для Windows и macOS. На Linux можно использовать Docker Engine с Compose.

1. В Telegram откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя и уникальный username. Сохраните полученный токен. [Инструкция Telegram](https://core.telegram.org/bots/tutorial#obtain-your-bot-token)

2. Создайте свой ключ [Groq](https://console.groq.com/keys) или [OpenRouter](https://openrouter.ai/settings/keys).

3. Склонируйте репозиторий.

   ```sh
   git clone https://github.com/Cheburek254/TelegramAIChatbot.git
   cd TelegramAIChatbot
   ```

   В Linux и macOS скопируйте шаблон так.

   ```sh
   cp .env.example .env
   chmod 600 .env
   ```

   В Windows PowerShell используйте эту команду.

   ```powershell
   Copy-Item .env.example .env
   ```

4. Откройте `.env` в редакторе. Заполните `BOT_TOKEN` и `POSTGRES_PASSWORD`. Для PostgreSQL задайте случайный пароль из менеджера паролей. Если в пароле есть знак `$`, заключите значение в одинарные кавычки. Выберите один из вариантов ниже и подставьте свой ключ вместо многоточия.

   **Groq** (настройка по умолчанию в примере)

   ```dotenv
   LLM_PROVIDER=groq
   GROQ_API_KEY=...
   GROQ_MODEL=openai/gpt-oss-120b
   ```

   [Модель GPT OSS 120B в каталоге Groq](https://console.groq.com/docs/model/openai/gpt-oss-120b)

   **OpenRouter**

   ```dotenv
   LLM_PROVIDER=openrouter
   OPENROUTER_API_KEY=...
   OPENROUTER_MODEL=nvidia/nemotron-3.5-super-vl:free
   ```

   Для OpenRouter бот принимает явный идентификатор с суффиксом `:free` и задаёт нулевые пределы цены. У бесплатных моделей есть ограничения провайдера. Если модель исчезнет из каталога, выберите другую `:free` с поддержкой инструментов и структурированных ответов. При заполнении обоих ключей бот может переключиться на резервного провайдера при ошибке основного. [Каталог OpenRouter](https://openrouter.ai/models)

5. Соберите и запустите контейнеры. Для первого запуска понадобится скачать базовые образы и зависимости.

   ```sh
   docker compose up -d --build --wait
   docker compose ps
   docker compose logs --tail=50 bot
   ```

6. Откройте своего бота в Telegram и отправьте `/start`, затем `/timezone Europe/Moscow` или укажите свою зону IANA, например `Europe/Berlin`. Выберите **Учёба** и отправьте «Объясни, что такое замыкание в Python».

Для обычного запуска входящие порты не нужны. Бот сам обращается к Telegram через polling, а PostgreSQL доступен контейнерам по внутренней сети. Один токен должен использоваться одним запущенным экземпляром.

## Примеры в Telegram

### Расписание

- `/schedule` открывает меню **Добавить / изменить занятия** и **Посмотреть расписание**. В просмотре можно выбрать сегодняшний день или текущую неделю. `/schedule 2027-01-11` открывает выбранную дату.
- Для добавления отправьте `/schedule add 2027-01-11 10:00-11:30 | Английский | Аудитория 301` и подтвердите. Номер записи из списка используется в `/schedule edit` и `/schedule delete`.
- Для повторения по нечётным неделям отправьте `/schedule repeat 2027-01-11 2027-05-31 1 odd 2027-01-11 10:00-11:30 | Английский | Аудитория 301`. Первые две даты задают период, `1` означает понедельник, а третья дата задаёт первую неделю. Используйте `all` для каждой недели и `even` для чётных. Подставьте свои даты. Всю серию можно удалить командой `/schedule delete_series НОМЕР`.

### Напоминания и сводка

- Разовое напоминание в режиме **Учёба**. Отправьте «Напомни завтра в 18:00 подготовить документы» или откройте `/reminders` и нажмите **Добавить напоминание**. В списке и под уведомлением доступны **Готово** и **Перенести**. Выберите быстрый перенос либо **Своя дата и время**.
- Ежедневное напоминание. Отправьте «Напомни каждый день в 19:00 повторить английский» или нажмите **Добавить ежедневное** в `/daily_reminders`. В карточке можно выбрать **Своё время** и дописать `ЧЧ:ММ`, отметить **Готово сегодня** или отключить серию. Время закрепляется за зоной напоминания. Можно включить до десяти ежедневных напоминаний.
- Сводка. Отправьте `/city Санкт-Петербург, Россия` и подтвердите город. Выберите время командой `/briefing_time 08:30` и включите сводку через `/briefing_on`. Она включает занятия, задачи, напоминания, погоду и тему для повторения. `/briefing_off` выключает сводку. Личные напоминания работают независимо.

### Задачи и дедлайны

Напишите «Сдать отчёт в пятницу до 18:00» или «Задача: разобрать конспект» и подтвердите карточку. Можно указать день недели, «завтра», дату в формате `ДД.ММ` или `ГГГГ-ММ-ДД`. Дата без времени означает 23:59. Для срока используется зона `/timezone` или зона по умолчанию.

В `/tasks` есть **Добавить задачу**. В карточке записи нажмите **Готово** или **Перенести**. Выберите быстрый перенос либо **Своя дата и время** и допишите, например, `2027-01-11 18:30`. Сводка показывает открытые задачи на сегодня, просроченные и без срока.

В режиме **Учёба** можно спросить «Какие у меня ближайшие дедлайны?», «Что просрочено по задачам?» или «Какие задачи у меня завтра?». Бот читает личные записи через MCP и показывает даты без пересказа моделью. Если ответ расписания слишком велик для контекста, бот выводит проверенные строки напрямую.

У задачи с дедлайном нажмите **За сколько минут оповестить?**, допишите число от 1 до 10 080 и подтвердите. При переносе срока оповещение пересчитывается, при завершении задачи отменяется. Для снятия оповещения используйте кнопку **Отключить оповещение** в карточке.

Напишите «Каждый день в 19:00 повторять английский» или «Каждую пятницу в 18:00 сдавать отчёт» и подтвердите. После **Готово** появится следующее вхождение с той же настройкой оповещения. Чтобы закончить серию, нажмите **Отключить повторение**.

В **Истории задач** можно искать по названию и возвращать задачи в открытые. Для повторяющейся задачи восстановление убирает следующее вхождение, если его ещё не меняли и оповещение по нему не отправлено.

Перешлите объявление с текстом или подписью. Бот передаст текст настроенной модели и предложит до шести задач с выдержками из объявления. Проверьте и подтвердите каждую нужную задачу отдельно.

Кнопки для команд с аргументами открывают черновик в текущем чате. Допишите данные и отправьте команду сами.

### Свободное время

Отправьте `/free 90 до пятницы следующей недели` или «Найди мне полтора часа до пятницы в 18:00, чтобы сдать отчёт». Дни следующей недели считаются от ближайшего будущего понедельника в вашем часовом поясе. Бот ищет между парами с 09:00 до 21:00 и учитывает дедлайн одноимённой открытой задачи. По умолчанию период составляет семь дней, с указанным сроком — до 14 дней. Используется актуальное расписание подключённого ИТМО или личный календарь. Кнопка под подходящим окном подтверждает разовое напоминание.

### Свои материалы

Отправьте в чат UTF-8-файл `.txt` или `.md` либо используйте `/materials add Название | Текст заметки`. После подтверждения спросите, например, «Объясни по моим материалам, как работает очередь». Через `/materials` можно посмотреть список, а через `/materials delete ID` удалить материал после подтверждения. Лимиты составляют 20 материалов на пользователя, 200 КБ на файл и 50 000 символов на текст.

## Опционально. HTTPS, расписание ИТМО и Telegram Mini App

HTTPS нужен для подключения my.itmo и запуска Mini App. Для обычного личного календаря в чате дополнительная настройка не нужна.

Откройте **Мой план** в меню личного чата или отправьте `/app`. В панели можно добавлять и изменять личные занятия, задачи и напоминания, переносить их и отмечать задачи готовыми. Изменения подтверждаются в самой панели.

В разделе **Напоминания** кнопка **Удалить** убирает разовую запись, а **Выключить** останавливает ежедневную серию. После подтверждения ожидающие отправки отменяются.

Кнопка **Подключить ИТМО** открывает вход и привязку аккаунта. Официальные пары отображаются отдельно от редактируемого личного расписания. Вкладка **Погода** показывает текущие условия и рекомендации для города из `/city`, по умолчанию Санкт-Петербург. Панель обслуживается на `/miniapp/` через тот же Caddy, что и вход в ИТМО.

Явные запросы к инструментам работают во всех режимах чата. Например, «Какие у меня пары седня?», «Шо по дедлайнам?», «Покажи мои материалы» и «Какая сейчас погода в СПб?». Без названия города используется город из `/city`, иначе Санкт-Петербург. Чтобы создать напоминание, задайте часовой пояс и напишите «Напомни завтра в 18:00 проверить отчёт». Бот запишет его после подтверждения.

Few-shot примеры покрывают все пять MCP-инструментов и помогают разбирать свободные формулировки.
Напоминания поддерживают относительное время, например «Напомни мне через пару минут проверить чай»,
«Напомни через полчаса про встречу», «Напомни через час и 15 минут проверить отчёт» или
«Напомни про встречу через два часа». «Пару» означает 2, «полтора часа» — 90 минут.
Поддерживаются «минутка», «минуточку», «секундочку», «часик», «денёк» и «недельку»,
а также формы с числом, например «через пару минуточек».
Отсчёт начинается с запроса. Бот показывает точный момент перед подтверждением.
Для «через несколько минут», «скоро» и «попозже» он попросит уточнение.
Свободные формулировки проходят через Router с примерами во всех режимах. Он определяет
смысл разговорных слов вроде «погодка», «парочки», «таски» и «конспектики» и уточняет
неоднозначные просьбы. Выбранный пользователем режим сохраняется.
Обращения и опечатки тоже допустимы, например «Ассистент, напоммни плиз через минутку про чай».
Модель извлекает намерение, текст и время в проверяемый черновик. Приложение рассчитывает
момент напоминания и запрашивает подтверждение. Просьба может стоять в любой части фразы.

После подключения используйте `/itmo_alerts on` или **Расписание → Посмотреть расписание → Изменения ИТМО** и подтвердите включение. Бот проверяет ближайшие семь дней примерно каждые 30 минут. Первое чтение задаёт исходное расписание, дальше бот сообщает о переносах, сменах аудитории, добавленных и убранных занятиях. Чтобы отключить уведомления, отправьте `/itmo_alerts off` и подтвердите.

1. На сервере направьте DNS-запись своего домена на сервер и сделайте порты 80 и 443 доступными для Caddy. Они должны быть свободны. [Как Caddy получает HTTPS-сертификат](https://caddyserver.com/docs/automatic-https)

2. В `.env` установите `ITMO_AUTH_PUBLIC_URL=https://bot.example.com`, подставив свой домен. Указывайте HTTPS-адрес без пути.

3. Запустите Compose с дополнительным файлом. Caddy принимает HTTPS и передаёт приложению только маршруты входа ИТМО.

   ```sh
   docker compose -f compose.yaml -f compose.itmo.yaml up -d --build --wait
   docker compose -f compose.yaml -f compose.itmo.yaml logs --tail=50 itmo-https
   ```

4. Отправьте боту `/itmo` и нажмите **Войти в ИТМО**. Откройте одноразовую ссылку, проверьте домен своего экземпляра, войдите и подтвердите подключение в Telegram. В Mini App откройте **Расписание → Подключить ИТМО** и подтвердите аккаунт там же. Вводите пароль только на доверенном экземпляре и не отправляйте его в чат.

После подключения обычные вопросы о расписании в режиме **Учёба** запрашивают актуальные данные my.itmo. В меню расписания можно отдельно сохранить ближайшие 14 дней как локальную копию. Импортируются только ещё не начавшиеся занятия. Если ИТМО требует дополнительные шаги входа или меняет форму, браузерное подключение может быть недоступно.

Кнопка **Отключить ИТМО** в чате и Mini App отзывает сессию бота после подтверждения. При отсутствии сохранённой настройки автоотключение срабатывает через 3 дня после входа. Установите срок от 1 до 365 дней, например `/itmo 14`. Отключение автоотзыва требует подтверждения и сопровождается предупреждением о риске кражи токена.

После отзыва доступна сохранённая выгрузка с пометкой об устаревании. Пока сессия действует, бот раз в день сохраняет расписание на ближайшие 14 дней. Для дат, которых в копии нет, бот показывает личное расписание и предупреждение. Повторный вход пользователь запускает сам. Если сервис ИТМО временно недоступен, бот сразу прекращает использовать отзываемый токен и повторяет запрос в фоне. Вручную скопированный токен удаляется из бота с сохранением исходного входа.

**Проверка ITMO.ID.** Два независимых входа A и B получили разные ID сессий. Ротация A выдала новый refresh-токен, при этом прежний ещё принимался. После отзыва A её обновление вернуло `invalid_grant`, а B, браузер и мобильное приложение продолжили работать. Уже выданный access-токен может оставаться действительным до своего срока истечения.

### Рабочая роль PostgreSQL и шифрование ИТМО

Запустите `python -m app.db_security` с параметрами администратора БД в окружении `POSTGRES_*`. Команда запросит отдельный пароль, применит схему и политики RLS. Для Compose укажите `BOT_DB_USER=study_assistant_runtime`, `BOT_DB_PASSWORD` и `POSTGRES_RLS=1`. При запуске напрямую укажите рабочую роль и пароль как `POSTGRES_USER` и `POSTGRES_PASSWORD` процесса бота. Повторяйте миграцию перед развёртыванием изменений схемы. Рабочая роль не имеет административных прав. Политики сверяют владельца в каждой транзакции.

На сервере разместите Fernet-ключ отдельно от каталога сессий с правами `0600` и владельцем UID 10001. Укажите `ITMO_VAULT_KEY_PATH` на хосте и `ITMO_VAULT_KEY_FILE=/run/secrets/itmo_vault_key` в Compose. Старые сессии шифруются при старте. На Linux временные данные SDK размещаются в `/dev/shm`. Ключ хранится отдельно от резервных копий сессий, хотя root работающего сервера может получить к нему доступ.

## Запуск Python для разработки

Нужен Python 3.12. Можно запустить только PostgreSQL в Docker и подключить приложение с компьютера. Заполните `.env` как для быстрого запуска.

```sh
docker compose -f compose.yaml -f compose.local.yaml up -d --wait db
python -m venv .venv
```

На Linux и macOS активируйте окружение через `source .venv/bin/activate`. В PowerShell можно вызвать `.\.venv\Scripts\Activate.ps1` или использовать `.\.venv\Scripts\python.exe` вместо `python` в следующих командах.

```sh
python -m pip install -r requirements.txt
python -m app
```

Для проверки запущенного процесса в другом терминале выполните `python -m app.healthcheck`. В этом режиме PostgreSQL опубликован только на `127.0.0.1`. Для своего PostgreSQL достаточно задать его адрес и учётные данные в `.env`. Перед запуском Python остановите контейнер бота, если он использует тот же токен. Для интеграции ИТМО используйте Docker-режим с Node.js внутри образа.

## Эксплуатация

```sh
docker compose ps
docker compose logs -f bot
docker compose exec bot python -m app.healthcheck
docker compose stop
```

Если использовали `compose.itmo.yaml`, передавайте оба файла и в командах управления. При обновлении выполните `git pull`, затем повторите команду запуска с `--build`. История и расписание хранятся в томе `postgres_data`, сессии ИТМО — в `itmo_state`. Сохраняйте резервные копии этих данных приватно. Обычный `docker compose down` сохраняет тома, а флаг `-v` удаляет их.

| Симптом | Что проверить |
| --- | --- |
| Бот не появляется онлайн | Посмотрите `docker compose logs --tail=80 bot`. Проверьте токен, доступ к Telegram и отсутствие другого процесса с тем же токеном. |
| Таймаут при подключении к Telegram | При прямом доступе оставьте `TELEGRAM_PROXY_URL` пустым. При необходимости используйте рабочий HTTP CONNECT или SOCKS5-прокси и повторите `docker compose up -d`. |
| Ошибка авторизации PostgreSQL | Сверьте пароль с тем, который использовался при создании тома. Смена `.env` сама по себе пароль роли не меняет. |
| Ошибка ответа модели или лимит | Проверьте ключ выбранного сервиса, доступность модели и квоту. |
| Расписание и напоминания сдвинуты | Сверьте зону через `/timezone`. Для ежедневного напоминания используется зона на момент его создания. |

Храните ключи и токены в локальном `.env`. Для генерации ответов приложение передаёт выбранному AI-провайдеру текст запроса, часть истории и релевантные данные инструментов. Учитывайте это перед отправкой конфиденциальных материалов. Доступ к боту также расходует квоту ключа его владельца.

## Устройство и проверки

Python и aiogram принимают сообщения. Режимы диалога работают с Groq или OpenRouter, а инструменты расписания, погоды и поиска материалов доступны через локальный MCP-процесс. PostgreSQL хранит историю, личные данные и очередь уведомлений. Планировщик восстанавливает незавершённую доставку после перезапуска и допускает ограниченные повторы при сетевых ошибках.

Персональный стиль речи применяется также к стартовому меню, заголовкам карточек, кнопкам и типовым уведомлениям. Даты, записи и команды сохраняются.

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
```

Интеграционные тесты запускаются на отдельной PostgreSQL в Docker. Для Linux и macOS используйте `RUN_INTEGRATION=1 python -m pytest -m integration -v`, а в PowerShell сначала задайте `$env:RUN_INTEGRATION='1'`.
